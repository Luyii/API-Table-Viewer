# 浏览器验收指南

适用版本：v1.5.1。返回 [文档中心](README.md)。

## 启动

需要 Node.js 18+，无依赖，无需 npm install。从仓库根目录执行：

```sh
npm run test:manual
```

打开 http://127.0.0.1:8765 。服务器仅监听 IPv4 回环地址；Ctrl+C 停止。端口冲突时 Linux/macOS 使用 `PORT=8877 npm run test:manual`；PowerShell 使用 `$env:PORT=8877; npm run test:manual`。按输出地址打开页面。不是双击 HTML，也不是打开扩展 panel.html。

在 chrome://extensions 开启开发者模式，加载直接含 manifest.json 的仓库根目录。更新扩展后重新加载并关闭、重开 DevTools。页面打开 DevTools → API Table，等待面板初始化后才点击案例按钮；每次请求有递增 run 参数且 no-store，避免缓存和去重妨碍复测。页面不自动发请求。可在 Network 检查原始 Response 对照。页面日志仅展示 300 字符，不代表响应被截断。

另运行 `npm test`：78 项回归、静态包检查，以及 `node --test tests/manual/check.cjs` 的 HTTP/Worker 联动检查。后者使用临时随机端口并自动关闭，不需要先启动手工服务器。

## 数据与触发点

| 按钮 / GET 路径 | 在扩展选择的数组或单元格 | 验收依据 |
| --- | --- | --- |
| ordinary | 根数组 | 260 行；amount 含 -12.5、-2、0、2、10；TABLE-HIT 在原索引 0、124、259 的 note 和 124 的 extra，共 3 行、4 单元格 |
| nested | groups[0].items、primitives、mixed、empty | 对象 / 原始值 / 混合 / 空数组；tags 也能独立查看 |
| nodes | 根表格第 1 行 payload；内层路径 $[0].payload | 6,000 个原始值，含根共 6,001 节点；末项 NODE-END-5999；字符量不足 500,000，明确由节点数触发提示 |
| records | 根表格第 1 行 records；内层路径 $[0].records | 50,000 条，每条 3 字段，共 200,001 节点；末条 id=50000、marker=RECORD-END-50000；响应低于 20 MiB |
| integers | 根数组 | 原文数字 9007199254740993、9007199254740992、9223372036854775807、-9223372036854775808，另含同值字符串用于类型对照 |
| long-text | 第 1 行 text / 第 2 行 text | 第 1 行约 36,000 字符，普通查看完整；第 2 行超过 500,000 字符，触发字符阈值并可分段；第 1 行第 2/3 个万字符段含 PAGE-2-MARK / PAGE-3-MARK |
| missing | 根数组 | 第 2 行缺 optional、nullable、empty；其他行含 null 与空串；空字段名排序后 id 顺序 3、1、2 |

所有路径均为 `/api/<案例名>`。POST /api/echo 原样回显合法 JSON（上限 1 MiB），页面按钮发送未加引号的超安全整数。/api/plain 返回 text/plain；/api/status 返回 422 JSON。服务不托管扩展资源或任意磁盘文件。

## 操作步骤

每轮先清空扩展请求，清空页面日志，重新发送对应案例。记录 Chrome 版本、OS、扩展版本、提交 SHA、页大小、缩放、实际行为、截图/导出文件名。问题记录应包含复现步骤和预期行为。

1. **捕获**：先开 API Table 再发 ordinary，预期请求出现且根数组可打开。单独测试 HAR 补录：先打开 Network，关闭本轮 API Table 面板初始化前发请求，再切到 API Table，检查已有请求是否补录；如面板早已初始化应重开 DevTools 重试。发 plain、422，再发 ordinary，非 JSON 不应进入 JSON 列表或阻断后续；422 JSON 应可查看。测试 URL、方法 POST、状态 422 筛选，再清空恢复。
2. **表格搜索定位**：ordinary 页大小设 100，先不筛选浏览第 1/2/3 页，TABLE-HIT 应位于上述原索引。搜索 TABLE-HIT 后只剩 3 行、4 单元格匹配。本案例筛选后不会跨 25 行分页，跨页定位使用下一步专门场景，不能把翻过原数据页当成筛选后跨页通过。
3. **跨页匹配专测**：ordinary 搜索 `中文用户-`，260 行均匹配。页大小 25，从首匹配连续“下一个”到第 26 个，预期进入第 2 页并滚动高亮；上一个返回第 25 个。搜索 TABLE-HIT 另验证 note → extra 的横向定位，隐藏 extra 再定位，检查实际显隐行为与定位一致，记录结果。
4. **排序与列宽**：清搜索，amount 升序应从 -12.5 至 10，降序相反。拖表头右边缘，预期宽度改变且不触发排序；翻页、搜索再清空后手动宽度保留；双击边缘恢复单列自动宽度，“适配列宽”重算全部。测试中文、数字和长列均为单行省略，表头、数值基线及横向滚动正常。missing 点空表头排序，升序 id=3/1/2；缺失字段显示 — 且不能打开不存在的路径，null 与空串可区分。
5. **数组和展开**：nested 各数组均能打开，empty 为 0 行。普通对象弹框默认全展开，点击“收起全部”后文字变“展开全部”，再点恢复；整行、Enter/空格、方向键操作和复制/进入按钮互不误触。手动折叠根节点时全局按钮同步。
6. **大节点和尺寸变化**：nodes 外层表格点击 payload（只选择内层数组打开表格不会触发弹框阈值）。预期先提示“节点超过 5,000 个”，确认后遍历完成并可滚到 NODE-END-5999。收起、展开、最大化/恢复、调整 DevTools 高度，预期无大块空白、漏行或重复行，能继续滚动。关闭后切换其他请求无持续任务干扰。
7. **50,000 行**：records 外层点 records 确认大数据弹框，再从数据结构选择 $[0].records 打开表格，页大小 100 共 500 页，末页末条 id=50000。表格搜索 RECORD-END-50000 应仅 1 行。弹框搜索同词，可能需多次“继续搜索下一批”扫描完（每批扫描有上限），点击结果应在原树展开并滚动高亮，末节点内容正确。记录滚动响应、内存和耗时。
8. **长文本与异步竞争**：long-text 第 1 行打开后能看到完整文本及两个段标记；第 2 行先提示字符阈值，确认后单独进入字符串分段视图。快速点击下一段/上一段，快速换搜索词，关弹框再开第 1 行，检查最终视图与最后操作一致，无旧响应覆盖。第 1 行普通字符串不会自动进入分段模式；要测分段竞争使用第 2 行。
9. **快捷键与剪贴板**：先点击扩展内部取得焦点，分别在表格和弹框测试 Ctrl/⌘+F、F3/Shift+F3、Enter/Shift+Enter、Esc，记录 Chrome 是否拦截。使用界面按钮作对照。复制原始响应、节点、路径、Markdown；粘贴到纯文本编辑器比对完整内容。POST echo 请求详情“复制请求体 JSON”应保留 9007199254740993 原文，不夹带 Headers；复制 cURL 可在终端对本地服务重放，响应应保留原文。
10. **导出**：ordinary 清过滤导出 CSV/JSON、复制 Markdown，应含 260 行；搜索 TABLE-HIT 后应含 3 行，导出含全部字段（隐藏列不应丢失）。排序 amount 后导出顺序与排序一致。CSV 含中文 BOM、真实 -12.5 不加单引号，字符串 =1+1 有公式防护；用文本编辑器核对引号、逗号和换行，不能用物理行数推断 CSV 记录数。integers 导出 JSON 数字字面量不应加引号或舍入，CSV/Markdown 保留全部数字。勿用原生 JSON.parse 或电子表格自动数值转换来判断大整数精度，直接核对文本。records 清过滤导出 JSON 应含 50,000 条并有末项；原始响应及当前节点下载内容分别对应整条响应和所选节点。检查实际下载文件、文件名及浏览器下载完成状态。

## 接口自动检查

`npm run test:fixtures` 从本地 HTTP 服务获取数据，再交给 worker.js 和 json-codec.js，检查以下内容：

- 节点阈值及完整遍历的末项。
- 50,000 条记录的分页、筛选和搜索。
- 超安全整数原文、列排序、字段路径和缺失值。
- 长文本完整显示与分段内容。
- 页面和脚本路由、POST 回显、413、422、404、405 及非 JSON 响应。

命令与执行记录汇总见 [测试说明](TESTING.md)。

## 字段级响应模拟验收

更新扩展后关闭、重开 DevTools 并刷新目标网页，以安装新的启动脚本。打开本地服务的 `/mock-debug`，自动加载订单。API Table 中选择 `/api/mock-orders`，打开 `data.records` 表格。

1. 双击 customerName，输入测试名称，Enter 提交；双击 amount 修改数值。观察轻微底色、顶部“编辑模式”和两处修改。Esc 应取消当前输入，失焦应提交；非法数字不能提交。
2. 网页点击 Fetch、XHR 查询，两者显示修改值，未改字段继续来自后端。Network 仍有真实请求。手动 / Ctrl+R / 强制刷新后，页面启动请求应继续得到修改值。
3. 清空插件捕获列表、关闭并重开 DevTools 后再请求，规则仍保留。顶部“查看修改”核对前后值，定位按钮进入对应字段，恢复一项只移除该字段。
4. 点击“退出编辑”，再请求或刷新，网页恢复真实值。退出本身不重渲染业务页面。另一个标签页 / 其他网站不继承规则。
5. 对 2 MiB+ 响应只修改小字段，确认没有整份编辑器的 1 MiB 限制。对象数组重新排序后仍修改相同 ID 的行；缺少 / 重复 ID 或字段类型变化时应跳过并在网页控制台提示。

自动测试通过不等于上述真实 Chrome 行为已验收，请记录实际浏览器版本和结果。
