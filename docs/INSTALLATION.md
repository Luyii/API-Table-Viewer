# 安装、更新与加载失败排查

1.5.0 需要 Chrome 114+。原位字段 Mock 使用 HTTP / HTTPS 网站访问权限和扩展会话存储。更新后必须刷新目标网页，才能让页面启动阶段的请求使用保留规则。

## 首次安装

1. 将 ZIP **完整解压**。GitHub 的源码 ZIP 通常还包含一层项目目录，请进入该目录确认能看到 `manifest.json`。
2. 建议放在固定路径，例如 Windows 的 `C:\ChromeExtensions\APITableViewer`，避免安装后移动或删除。
3. Chrome 地址栏输入 `chrome://extensions`，开启右上角“开发者模式”。
4. 点击“加载已解压的扩展程序”，选择直接包含 `manifest.json` 的文件夹。
5. 在目标网页打开 DevTools。标签较多时，在 `»` 菜单中查找 **API Table**。
6. 刷新目标网页，等待 JSON 接口完成并从左侧选择。

直接加载仓库根目录即可使用，不需要先打包。项目是 DevTools 面板，网页工具栏中没有独立业务弹窗。

## 更新

1. 关闭现有 DevTools。
2. 将新版解压并替换原目录中的源码文件，或在扩展管理页重新选择新版目录。
3. 在扩展管理页点击“重新加载”。
4. 重新打开 DevTools 并刷新网页。

请求缓存属于面板会话，关闭面板后不会作为历史接口库持久保存；布局和部分偏好会保留。

## 常见问题

| 现象 | 排查步骤 |
| --- | --- |
| `File path cannot be resolved` / 无法加载清单 | 先完整解压，确认目录实际存在且可访问；选择含清单的本地文件夹，不能选择 ZIP 或压缩包预览中的目录 |
| 选择了目录但找不到清单 | 检查是否多一层 `api-table-viewer-main` 等外层文件夹；不要选择 `docs`、`tests` 或 `dist` 父目录 |
| 路径含 `~` | 在 Windows 文件选择器使用真实绝对路径，例如 `C:\ChromeExtensions\APITableViewer` |
| 看不到 API Table | 扩展重新加载后关闭并重新打开 DevTools，在标签溢出菜单查找 |
| 列表为空 | 在 DevTools 打开时刷新页面并触发接口；确认响应为合法 JSON、未超过 20 MiB，且 DevTools 能读取响应体 |
| 旧请求没有完整响应 | 已有 HAR 补录仅限 Chrome 能读取的响应，刷新页面重新发起请求 |
| 快捷键未跳转 | 先点击扩展面板，确认搜索已有匹配；也可直接使用界面中的上一项 / 下一项 |
| 请求体复制按钮禁用 | 没有请求体、请求体不是 JSON，或已因体积限制截断；在 Chrome Network 中查看原请求 |

如果仍然失败，提供 Chrome 版本、操作步骤、扩展管理页的具体错误，以及脱敏后的最小 JSON 样例。请不要提供 Cookie、Token 或真实业务敏感数据。
