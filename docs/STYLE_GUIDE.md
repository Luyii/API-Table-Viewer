# 文档规范

本规范用于保持项目文档的结构、术语与验证信息一致。它是项目维护约定，不是外部认证声明。

## 文档职责

- README：项目定位、能力、快速开始、边界与导航，不堆叠完整历史版本介绍。
- 操作指南：给出前提、步骤和预期结果；排查指南按现象组织。
- 开发参考：描述模块、数据流、接口与约束，不重复安装流程。
- 测试文档：区分执行方法、当前验证结果和历史记录。
- 版本说明：描述特定版本的能力、行为变化、升级步骤及限制。

组织方式参考 [Diátaxis](https://diataxis.fr/)。保持现有路径兼容，不为形式建立空目录或占位文档。

## 标题与语言

- 每份文档只有一个一级标题，按二级、三级顺序分节，不跳级。
- 正文使用简体中文；API Table Viewer、Chrome DevTools、JSON、Fetch、XHR 等标准名称保留英文。
- 版本说明标题使用 `v<版本号>：<更新主题>`，例如“v1.5.1：查看器交互与请求捕获修复”。
- 普通文档标题使用名词短语，例如“使用指南”“测试与验证”，避免口号、问句和中英文重复标题。
- 中文与英文标识或数字之间保留必要空格；中文连续术语内部不额外插空格。

## 术语

| 统一称呼 | 含义 |
| --- | --- |
| 字段级响应模拟 | 保存字段补丁并在真实响应后应用；首次出现时可补充英文 Mock |
| 标量 | 字符串、数字、布尔值与 null |
| 扁平展开 | 展开某数组的全部后代层级，保留逐行折叠能力 |
| 一级展示 | 展示当前节点的直接子项，不递归展开其后代 |
| 主区域统一滚动 | 内嵌展开区不设置独立高度上限或纵向滚动口 |
| 版本说明 | 对应版本的用户说明；不表示已创建 GitHub Release |

文件名、命令、API 名称、界面标签和历史原始记录按实际内容保留，不机械翻译。

## 命令与示例

- 命令注明工作目录、环境要求和预期结果；代码块使用合适的语言标记。
- 示例使用虚构、脱敏数据，不包含真实域名凭证、Cookie、Token 或客户响应。
- 相对链接指向现有文件；标题变化后同步更新锚点，不生成不存在的标签或 Release 链接。
- 表格用于精确对照，步骤使用有序列表，避免重复描述同一行为。

## 版本记录

参考 [Keep a Changelog](https://keepachangelog.com/en/1.1.0/)：按版本倒序，区分未发布内容，按“新增、调整、修复”等类型记录用户可感知的变更。

日期使用 `YYYY-MM-DD`；只填写有记录可核实的日期。版本号以 `package.json` 和 `manifest.json` 为准，文档整理不单独增加产品版本号。

## 验证与维护

- 明确区分模拟 DOM / DevTools 的自动检查、真实浏览器手工验收和 CI 结果。
- 性能数字说明样本、规模、环境和测量范围；缺少条件时只保留为历史观察，不推断普遍性能。
- 不编造支持矩阵、响应承诺、许可证、日期、测试数量或安全认证。
- 功能变化时同步使用指南、参考、版本记录及相关验证说明；历史记录移动到归档并注明适用阶段。
- 文档提交至少检查相对链接、内部锚点、标题层级和失效术语。
