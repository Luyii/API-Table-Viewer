# v1.5.0 · 原位字段响应模拟

**从接口观察，到字段级调试。**

API Table Viewer 1.5.0 把调试入口放到数据本身：双击字段、输入测试值，然后让页面重新查询。无需修改业务代码、启动独立 响应模拟服务或反复粘贴整份 JSON。

## 这次更新解决什么

真实数据经常不方便触发边界场景：超长用户名、负数金额、异常枚举、布尔开关。为几处字段更改维护整份响应，容易覆盖无关的后端变化，也增加了操作成本。

1.5.0 只记录修改字段。请求继续访问真实后端，响应返回后再应用补丁；没有修改的字段继续更新。刷新页面时规则自动恢复，调试可以围绕同一组边界数据反复进行。

## 四步完成一次调试

1. DevTools → API Table 中选择接口，在表格、数据树或查看器中找到目标值。
2. 双击或按 F2 编辑，Enter / 失焦提交；Esc 取消当前输入。
3. 回到网页重新查询或刷新，观察业务页面的展示和逻辑。
4. 在顶部查看、定位、恢复某项修改，或点击“退出编辑”结束当前网站的 Mock。

已改字段使用轻微底色标记，悬停可查看原值。修改清单记录接口、路径、前后值，切换接口后仍可定位。清空捕获列表不清空规则。

## 字段级补丁，而非整份响应副本

编辑配置保存字段路径、原始类型、原值、新值和必要的数组标识，不将完整响应作为每次编辑的载荷，也不在每次输入时遍历整份 JSON 做 diff。

例如，只修改 `data.records[0].amount`，配置还会记录该行的唯一订单 ID。后端返回不同排序时，补丁先重新定位订单，再修改金额。若标识不存在、重复，或字段类型改变，该修改会跳过并在网页控制台提示，不盲目沿用旧行号。

超过 1 MiB 的响应仍可修改小字段。响应载入上限为 20 MiB，单字段编辑上限为 64 KiB。字段补丁减少了编辑阶段的通信与对比工作；每次匹配响应仍需解析和序列化，不承诺零开销。

## 刷新为什么还能继续用

页面 MAIN world 的脚本在 `document_start` 接管 Fetch / XHR。隔离脚本向扩展后台读取当前标签页、当前网站的会话配置，启动请求等待初始化后再发出；初始化异常超时则回退真实响应。

配置保存在 `chrome.storage.session`。普通刷新、强制刷新、清空列表和重开 DevTools 都不会主动清除。其他网站、其他标签页不会继承；关闭标签页、重启浏览器或重新加载扩展后清除。

## 支持范围

- Chrome 114+，Manifest V3，新增 HTTP / HTTPS 网站访问和 `storage` 权限。
- 主页面 Fetch、异步 XHR 的 JSON 文本 / JSON 响应；不覆盖 iframe、Worker、WebSocket 或流式协议。
- 按方法和完整 URL（含查询参数）匹配，不区分同 URL 的不同请求体。
- 修改已有标量并保持原类型；不新增 / 删除字段，不调整数组结构，不修改用于数组定位的标识。
- 最多 30 个接口、每接口 200 个字段、1 MiB 规则配置。

请求仍然执行真实后端操作。页面需要再次请求才能显示修改；退出也不直接改写已渲染的组件状态。原始捕获与导出不被补丁覆盖。数据只在本地处理，不加载远程代码、不上传响应。

## 验证

本地执行 `npm test`，覆盖 88 项回归、8 个 HTTP / Worker 子案例、13 项字段响应模拟 检查、18 项旧替换引擎回归、3 项预览检查，以及资源 / CSP / 脚本检查。打包后运行 `python3 tests/package-archive.py` 检查文件白名单、内容一致性和解压资源。

字段响应模拟 测试包含精确整数、数组重排、2 MiB 响应的小字段补丁、Fetch / XHR、启动请求等待、后台重启后的会话读取、站点 / 标签页隔离、取消、退出和重复初始化。另用模拟 DOM 执行实际面板与 Worker 检查原位编辑交互。

自动测试中的 DOM、XHR 和 Chrome API 有模拟，不代表真实 Chrome 兼容性与业务页面渲染已全部验收。仓库提供 `/mock-debug` 真实 HTTP 订单页面及[手工步骤](CHROME_REPRO.md)；GitHub Actions 的运行结果以对应提交为准。

## 更新

关闭 DevTools，将新文件替换到原扩展目录，在 `chrome://extensions` 重新加载扩展，再刷新目标网页。重新加载扩展会清空旧会话规则，请重新设置需要的字段修改。
